# E2E Gaps (#1079) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the four E2E holes in the Playwright SPA suite that stand between us and automating M9's "manual approval of every screen, across all five phases" gate.

**Architecture:** All work lands in `playwright-tests/`, except one small Rails change: `whats_the_magic_word` (the `?opensesame=<mode>` phase lever) moves from `HomeController` up to `ApplicationController`, so any path — including `/app/*` and the post-cutover `/` — can set the phase for its own session. That is what lets the new phase spec drive all five modes without touching a legacy HAML page.

**Tech Stack:** Playwright + `@axe-core/playwright` (chromium, `workers: 1`), React 19 + TypeScript SPA, Rails 8.1 API, Biome, RSpec.

**Spec:** [swapmyvote#1079](https://github.com/swapmyvote/swapmyvote/issues/1079), under epic [#1077](https://github.com/swapmyvote/swapmyvote/issues/1077). Background: [`docs/frontend-modernization-plan.md`](../../frontend-modernization-plan.md).

## Global Constraints

- **Never flip a canonical route to React.** Every path a spec navigates to comes from `spaPaths` (`app/frontend/lib/spaPaths.ts`). No new hardcoded `/app/...` string literals in specs, and no new dependency on a legacy HAML path.
- **Quality gates before every commit:** `corepack yarn lint:fix`, `corepack yarn typecheck`, `corepack yarn test`, and `bundle exec rspec` when Ruby changed. All must pass.
- **Ruby is pinned to 3.3.12 via rbenv** and a system Ruby may shadow it — prefix Ruby commands with `PATH="$HOME/.rbenv/shims:$PATH"`.
- **The E2E stack must be running or bootable:** `corepack yarn e2e` boots `foreman start -f Procfile.dev` itself, but foreman must be on PATH (`gem install foreman`) and the dev DB must exist (`bin/rails db:create db:schema:load`).
- **TypeScript style:** always braces in `if`/`else`/`for`/`while` bodies, even single-statement.
- **Styling:** Bootstrap utility classes over custom CSS; no inline `style={{…}}` for static values.
- **Fixture isolation:** every new spec file that seeds a user passes its own `suffix` to `seedProfileUser` / `seedSwapPair` (see the docstrings in `playwright-tests/support/seedProfileUser.ts`). Never share a mutable fixture row across spec files.
- **Do not widen scope into #1074 (suite flakiness) or #1058 (mobile viewport).** Both are separately tracked.

### Task 1: Move the `opensesame` phase lever to `ApplicationController`

`AppModeConcern#app_mode` already prefers `session[:sesame]` over `ENV["SWAPMYVOTE_MODE"]`, and it is reachable from every controller (`ApplicationController` includes `ApplicationHelper`, which does `include ::AppModeConcern`). But the only code that *writes* `session[:sesame]` is `HomeController#whats_the_magic_word`, registered as a `before_action` on that controller alone. So today a phase can only be set by visiting the legacy HAML `/`.

Two reasons to move it: the E2E phase spec should not depend on a legacy page it is meant to outlive, and at cutover `/` becomes `SpaController` and the lever disappears entirely. This settles the open question in #1079.

This grants no new capability — `?opensesame=` is already reachable by anyone via `/`; it only adds entry points.

**Files:**
- Modify: `app/controllers/application_controller.rb`
- Modify: `app/controllers/home_controller.rb:4` and `app/controllers/home_controller.rb:82-88`
- Test: `spec/requests/app_mode_sesame_spec.rb` (create)

**Interfaces:**
- Produces: `ApplicationController#whats_the_magic_word` runs as a `before_action` on every controller, so `GET <any path>?opensesame=<mode>` sets `session[:sesame]` and `?closesesame` clears it. Task 3 consumes this.

    elsif params.key?(:closesesame)
      session.delete :sesame
    end
  end

### Task 2: Re-point `signIn()` at the React login form

`playwright-tests/support/auth.ts:12` still does `page.goto("/users/sign_in")` and waits on the legacy layout's "Log out" link. Its own docstring says this predates M5; M5 shipped in #1053. Consequences: every signed-in spec enters the SPA through a HAML form, the React login form is exercised by exactly one test, and this is the last hardcoded legacy path in the suite — so it breaks at cutover while everything else flips with a single `spaPaths` edit.

The signed-in signal changes too. The legacy layout renders a bare "Log out" link; the SPA puts log out inside a dropdown whose toggle carries `id="user-menu"` (`app/frontend/components/navigation/Navigation.tsx`). Use that id rather than the toggle's accessible name — the name is the user's own name, which differs per fixture, and `User#name` appends " (test user)" for `@example.com` addresses.

**Interfaces:**
- Consumes: `spaPaths.login` from `@/lib/spaPaths`.
- Produces: `signIn(page, credentials): Promise<void>` — same signature as today, so no caller changes. Also exports `userMenu(page): Locator` for specs that want to assert the logged-in nav.

  page: Page,
  { email, password }: TestCredentials,
): Promise<void> {
  await page.goto(spaPaths.login);
  await page.getByLabel("Email").fill(email);
  await page.getByLabel("Password").fill(password);

### Task 3: Drive all five `SWAPMYVOTE_MODE` phases end-to-end

`AppModeConcern::VALID_MODES` gates most of the app, and `Home.tsx` picks one of five screens from it. Every existing E2E runs in whatever mode the stack booted in (`open`, the default), so four of the five screens and every phase gate are covered only by component tests against a stubbed `AppModeContext`. The server/client agreement on phase is untested.

Each phase asserts on **both sides**: the UI withholds the affordance *and* the API refuses the call. That pairing is the point — `RequireLoginsOpen` / `RequireSwappingOpen` say in their own docstrings that they are "UX only", so a test of the UI alone proves nothing about enforcement.

Playwright gives each test its own browser context, so `session[:sesame]` is per-test and needs no cleanup.

**Files:**
- Create: `playwright-tests/support/appMode.ts`
- Create: `playwright-tests/appMode.spec.ts`

**Interfaces:**
- Consumes: `whats_the_magic_word` on `ApplicationController` (Task 1); `signIn` and `userMenu` from `./support/auth` (Task 2).
- Produces: `setAppMode(page, mode)` and the `AppMode` union, for any later spec that needs a phase.

- [ ] **Step 1: Write the phase helper**

Create `playwright-tests/support/appMode.ts`:

```ts
import type { Page } from "@playwright/test";
import { spaPaths } from "@/lib/spaPaths";

/** AppModeConcern::VALID_MODES, in the order that file declares them. */
export const appModes = [
  "closed-warm-up",
  "open",
  "closed-and-voting",
  "open-and-voting",
  "closed-wind-down",
] as const;

export type AppMode = (typeof appModes)[number];

/**
 * Puts this browser context's session into one operational phase and lands on
 * the home screen for it.
 *
 * `?opensesame=` is `ApplicationController#whats_the_magic_word`, which stashes
 * the mode in `session[:sesame]`; `AppModeConcern#app_mode` prefers that over
 * `ENV["SWAPMYVOTE_MODE"]`. So the phase is per-session — and Playwright gives
 * each test its own browser context, so tests cannot leak a phase into each
 * other and nothing needs clearing afterwards.
 *
 * This is a full page load on purpose. The phase reaches React through
 * `GET /api/v1/session`, and a fresh document refetches it; a client-side
 * navigation would race the cached session against the new cookie.
 */
export async function setAppMode(page: Page, mode: AppMode): Promise<void> {
  await page.goto(`${spaPaths.home}?opensesame=${mode}`);
}
```

    // the point of this spec is the server, reached directly. `page.request`

    expect(await response.json()).toMatchObject({

 * Stand in for postcodes.io.
 *
 * `lib/postcodes.ts` calls it directly rather than going through our backend
 * (deliberately — see its header comment), so a spec that really hit it would
 * put a third party's uptime in CI's path. Everything downstream of this one
 * call stays real: our constituency list, POST /api/v1/pre_populate, and the
 * handoff to sign-up.
 */
async function mockPostcodeLookup(
  page: Page,
  result: { onsId: string; name: string } | { status: number; error: string },
) {
  await page.route("https://api.postcodes.io/postcodes/*", async (route) => {
    if ("status" in result) {
      await route.fulfill({
        status: result.status,
        contentType: "application/json",
        body: JSON.stringify({ error: result.error }),
      });
      return;
    }
    await route.fulfill({
      status: 200,
      contentType: "application/json",
      body: JSON.stringify({
        result: {
          parliamentary_constituency_2024: result.name,
          codes: { parliamentary_constituency_2024: result.onsId },
        },
      }),
    });
  });
}
